# P00 — ভিত্তি: কমিট, CI, staging, টেস্ট হারনেস

**লক্ষ্য:** বর্তমান কাজ নিরাপদে git-এ, প্রতি পুশে CI, একটি staging পরিবেশ। এই ফেজে কোনো নতুন ফিচার নয়।
**পূর্বশর্ত:** নেই। **পড়ুন:** `00_GROUND_RULES.md`, `08_AUDIT_TRACEABILITY.md`।

## টাস্ক

1. **N3 — বর্তমান uncommitted কাজ কমিট:** `git status` দেখাও। পুরনো ফিক্স প্ল্যানের ফেজ ০, ১, ২ অনুযায়ী আলাদা কমিটে ভাগ করার প্রস্তাব দাও (কোন ফাইল কোন কমিটে), অনুমোদনের পর কমিট। কোনো ফাইল বাদ যাবে না।
2. `npm run typecheck`, `npm run lint`, `npm test` চালাও; ফল দেখাও। লাল হলে এই ফেজেই ঠিক করো (L1, L2, L17 যাচাই)।
3. GitHub-এ push (মালিক নিজে remote দেখাবেন/অনুমতি দেবেন)। `.github/workflows/ci.yml` চলছে ও সবুজ কিনা নিশ্চিত করো (H16, H17)।
4. **v2 ব্রাঞ্চ:** `v2` নামে ব্রাঞ্চ; v2-এর সব কাজ এখানে, প্রতি ফেজ শেষে `main`-এ মার্জ মালিকের অনুমতিতে।
5. **বাতিল:** P14-এর আগে সার্ভার/staging নয়, লোকাল `meridian_practice` DB ব্যবহার হবে।
6. **টেস্ট হারনেস:** `src/tests/helpers/`:
   - `testOrg()` — খালি org + branch + warehouse + owner ইউজার + সিড চার্ট
   - `factories` — পণ্য, কাস্টমার, Vendor (পরে ফেজে বাড়বে)
   - `concurrently(n, fn)` — `Promise.all` সহায়ক
   - টেস্ট শেষে org-এর সব সারি মোছা
7. **C1/C2 যাচাই:** নতুন খালি DB-তে `prisma db seed` (SEED_DEMO ছাড়া) → কোনো DEMO পণ্য/সেল নেই; দুইবার সিড → permission মোছে না। টেস্ট আছে কিনা দেখো, না থাকলে লেখো।
8. **D1/D2/O2/U4 যাচাই:** Prisma singleton, `connection_limit`, `next.config` CPU সেটিং কমিটে আছে।
9. **পুরনো ডকে নির্দেশ:** `docs/BUSINESS_RULES.md`, `ARCHITECTURE.md`, `FIX_PLAN.md`-এর শুরুতে এক লাইন: "v2 কাজের জন্য `docs/v2/` দেখুন; সংঘাতে v2 জিতবে।"
10. `next.config`: `poweredByHeader: false` (LV-6 আংশিক, এক লাইন)।

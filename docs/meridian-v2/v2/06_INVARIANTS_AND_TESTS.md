# ইনভেরিয়েন্ট ও টেস্ট কৌশল

ইনভেরিয়েন্ট = যে নিয়ম সিস্টেমে কখনো ভাঙবে না। প্রতিটি তিন জায়গায় জোর করা হয়: (ক) পোস্টিং ইঞ্জিন commit-এর আগে, (খ) টেস্ট স্যুটে, (গ) দৈনিক রিকনসিলিয়েশন জবে।

## ৩. `assertBooksReconcile(orgId)`

P02-এ বানানো হয়েছে (`src/core/reconcile`), প্রতিটি ইন্টিগ্রেশন টেস্টের শেষে ও দৈনিক জবে চলবে। I1, I2, I4, I6, I7, I8, I15 যাচাই করে; ব্যর্থ হলে কোন অ্যাকাউন্ট/পণ্য/পার্টি এবং পার্থক্য সহ এরর দেয় (`BooksReconcileError.findings`)। **I6 এখন শুধু সতর্কতা** (`warnings`, ব্রাঞ্চ ধরে ইনভেন্টরি অ্যাকাউন্ট বনাম স্টকমূল্য, ≤ ১.০০ সহনীয়) — স্টক মূল্যায়ন সম্পূর্ণ হলে (P03) কঠোর হবে; আগেই কঠোর চাইলে `assertBooksReconcile(orgId, db, { strictInventory: true })`। কোনো ডাটাবেসে হাতে চালাতে: `scripts/reconcile.ts` (শুধু পড়ে, লাইভ সাইটে চলে না)। টেস্টে হিসাবের সাথে মেলানো স্টকের জন্য `stockedProduct(t)` (স্টক ব্যালান্স + লেজার + ওপেনিং জার্নাল)।

## ৪. গোল্ডেন ডাটাসেট (P11)

`src/tests/golden/agri-day.ts`: Green Agricare-এর মতো একটি দিন — ৩টি পণ্য (সার বস্তা, কীটনাশক বোতল লটসহ, বীজ প্যাকেট), Retail ও Wholesale দাম, opening, একটি ক্রয় পরিবহন খরচসহ, POS নগদ বিক্রি, bKash বিক্রি চার্জসহ, কুরিয়ার COD অর্ডার, আংশিক রিটার্ন, একটি ড্যামেজ, একটি Take-off, ভাড়া খরচ, contra। প্রতিটি ১০টি দৈনিক রিপোর্টের প্রত্যাশিত সংখ্যা ফাইলে হাতে লেখা; টেস্ট রিপোর্ট চালিয়ে মেলায়।

## ৫. CI গেট

প্রতি PR/পুশ: install → migrate (টেস্ট DB) → typecheck → lint → unit → integration → concurrency → golden → build। staging ডিপ্লয়ের পর E2E। যেকোনো লাল = মার্জ নয়।
